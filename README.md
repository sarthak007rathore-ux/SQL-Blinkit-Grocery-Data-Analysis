# Blinkit Grocery Data Analysis

This project performs an in-depth analysis of Blinkit grocery sales data using **SQL Server**. The objective is to clean the raw data, calculate important Key Performance Indicators (KPIs), perform granular sales analysis, and prepare SQL results that can be used for data visualization.

---

## Dataset

The dataset used for this analysis is **Blinkit Grocery Data**. It contains transactional information about products sold through different Blinkit outlets.

### Dataset Columns

* `Item_Fat_Content` – Fat content of the product, such as Low Fat and Regular.
* `Item_Identifier` – Unique identifier for each product.
* `Item_Type` – Product category, such as Fruits and Vegetables, Frozen Foods, Canned, etc.
* `Outlet_Establishment_Year` – Year in which the outlet was established.
* `Outlet_Identifier` – Unique identifier for each outlet.
* `Outlet_Location_Type` – Outlet location category, such as Tier 1, Tier 2, and Tier 3.
* `Outlet_Size` – Size of the outlet, such as Small, Medium, and High.
* `Outlet_Type` – Type of outlet, such as Supermarket Type1, Supermarket Type2, Supermarket Type3, and Grocery Store.
* `Item_Visibility` – Visibility of the product in the outlet.
* `Item_Weight` – Weight of the product.
* `Total_Sales` – Total sales/revenue generated by the product.
* `Rating` – Customer rating for the product.

---

## SQL Analysis

The analysis was performed using SQL queries in **Microsoft SQL Server**. The SQL workflow is divided into four major areas:

1. **Data Cleaning**
2. **Key Performance Indicators (KPIs)**
3. **Granular Analysis**
4. **Chart-Ready Analysis**

---

## 1. Data Cleaning

The first stage of the project focuses on preparing the data for analysis.

The `Item_Fat_Content` column contained inconsistent values such as:

* `LF`
* `low fat`
* `Low Fat`
* `reg`
* `Regular`

These values were standardized using a SQL `CASE` statement so that equivalent categories are represented consistently.

The cleaned categories include:

* **Low Fat**
* **Regular**

A `SELECT DISTINCT` query was then used to verify that the cleaning process was successful.

## 2. Key Performance Indicators (KPIs)

The second stage calculates the major business KPIs required to understand the overall performance of the Blinkit dataset.

### KPIs Calculated

* **Total Sales** – Overall revenue generated from all items.
* **Average Sales** – Average revenue generated per item/sale.
* **Number of Items** – Total number of records/items analyzed.
* **Average Rating** – Average customer rating.

The analysis also includes a focused calculation for outlets established in **2022**, allowing sales performance for that outlet-establishment year to be examined separately.

### KPI Results from the SQL Analysis

The analysis shown in the screenshot includes:

* Total Sales: **1.20 million**
* Sales for 2022 outlets: **0.13 million**
* Average Sales for 2022 outlets: **142**
* Number of Items for 2022 outlets: **928**
* Average Rating: **3.00**

## 3. Granular Analysis

* Total Sales

* Number of Items
* Average Rating

This helps identify how product fat content is associated with overall sales performance.

### Sales by Item Type

Sales are also analyzed across different product categories to identify which item types contribute most to revenue.

### Sales by Outlet

The analysis compares outlets using dimensions such as:

* Outlet location type
* Outlet size

## Key Insights

Based on the SQL analysis:

* **Low Fat products** generate higher total sales than Regular products in the analyzed dataset.
* **Medium-sized outlets** contribute the largest percentage of total sales among the outlet-size categories.
* **Tier 3 outlets** contribute the highest share of sales among the three location tiers.
* **Supermarket Type1** contributes the highest total sales among the outlet types shown in the analysis.
* The average customer rating is approximately **3.00**.
* The SQL queries transform the raw dataset into structured outputs suitable for reporting and visualization.
